# Fitness Hub 0.3.1 — historical scale import hardening

Development/test APK, not a production or medically validated release.

## Changes

- Validated SmartScaleConnect CSV rows are imported in one Room transaction; a persistence failure rolls back that batch.
- Reimporting a measurement skips its composition too instead of trying another insert with a new primary key and the same unique timestamp.
- Recomputing local estimates reuses the stored primary key and cannot overwrite an imported vendor composition.
- Exact user-name matching prevents profiles differing only in case from being treated as one person. In mixed named/unnamed files, unowned rows are skipped when a named profile is selected.
- CSV validation rejects duplicate headers, shifted/truncated rows and malformed quotes before writing. BOM, CRLF, escaped quotes and quoted decimal commas are supported.
- Impossible dates are not silently normalized. Explicit offsets are preserved; local timestamps in daylight-saving gaps or overlaps are skipped rather than guessed.
- Parser/persistence work runs off the main thread. Storage errors are sanitized and coroutine cancellation propagates.
- CI records JUnit counts, retains test/lint reports, verifies the APK signature against the existing public test certificate and publishes a SHA-256 checksum.
- Publication uploads the new APK before updating the rolling tag; it no longer deletes the entire previous release first.

## How to test on the phone

1. Install the APK from this release. Builds 0.3.0 and 0.3.1 use the same test key and application ID; 0.3.1 increments versionCode to 3. Physical upgrade testing remains required.
2. In Settings, open the Xiaomi history importer and select a SmartScaleConnect CSV containing only the intended person's records. If more than one user is listed, enter the exact profile name and retry.
3. Check dates, weight and supported composition fields against the original export. Import the same file twice: the second import should report duplicates, not add measurements.
4. Check the Body history. No automatic Xiaomi-cloud login or Health Connect write-back has been added by this release.

SmartScaleConnect's timezone-free timestamps are interpreted in the phone's timezone. Use the same timezone as the export; ambiguous local times are not imported. The single-user app does not implement a multi-profile archive: do not deliberately combine different people's separate exports.

## Validation boundaries

The added JVM tests cover parsing, profile filtering, duplicate handling, DAO default-method logic, failure handling and cancellation. They are not physical S400 tests and do not execute Room's generated SQLite transaction code. Full Room migration/rollback instrumentation, live BLE firmware compatibility and real Health Connect data remain to be tested.

Backup is still a prototype and must not be assumed to restore every data table losslessly. Do not uninstall an older build containing valuable data solely to resolve a signing mismatch. Preserve independent exports first. The legacy Open Health Hub package and the Fitness Hub package are separate app identities.

The repository's signing key is deliberately public and TEST-ONLY. It does not authenticate the publisher against third parties who also possess that key. Install test APKs only from this repository; production distribution requires a separate private signing identity. A published checksum detects a corrupted download but is not a substitute for a private publisher signature.
