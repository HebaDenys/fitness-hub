# Fitness Hub 0.3.2 — Xiaomi protocol prerequisite and privacy hardening

Development/test build. This release does **not** add a working Xiaomi login or automatic cloud synchronization. It implements the next executable prerequisite from the approved plan, rather than presenting an unconnected button as a finished integration.

## Implemented

- `FH-XIA-01`: isolated Kotlin Xiaomi request descriptors, strict bounded JSON parser, typed scale responses and sequential paginated-reader contracts. The formats and read endpoints are traced to SmartScaleConnect commit `a9e5c04f1079b65d456c8a5fd296775a1ef29e8f` (MIT); its notice is included in the APK.
- Three `fromSource` formats, numeric/string fields, nested composition and correct distinction between measurement time and page cursor. Missing, malformed, conflicting, unknown-unit and future values are represented explicitly rather than silently repaired.
- Subject/account/device metadata are retained separately. Missing or conflicting subject IDs are not replaced with names, weight guesses or the logged-in user's ID.
- Repeated/non-advancing pages, malformed JSON, unexpected response order/size and vendor errors fail explicitly. Pagination advances only after the injected page committer succeeds; a page budget produces a resumable pause, not false completion.
- Per-metric vendor estimates remain estimates. Unknown numeric extensions retain their representation without fabricated units; unknown text/sensitive fields are omitted and flagged. This is not yet a lossless importer for all possible vendor fields.
- Operational log allowlists now enforce allowed event names, count types and error labels instead of stringifying arbitrary fields/objects.
- Android automatic backup and device transfer are explicitly excluded through legacy and modern XML rules; cleartext traffic is explicitly disabled. User-selected file exports remain available.

## What changes on the phone

Most changes are inside the engine; the existing UI remains. No Xiaomi credentials are requested by this release. APK package and test signing key remain unchanged; versionCode increases from 3 to 4.

**Important recovery limitation:** automatic OS cloud backup/device transfer are now explicitly opted out. Existing portable backup is still incomplete. Keep original vendor data and independent copies of irreplaceable entries; do not uninstall a build holding important data based on an assumption of complete restore. The new policy does not delete older backups already held by another provider. A document-picker destination chosen by the user may itself be cloud-backed.

## Verification boundaries

The added tests exercise pure protocol/JSON parsing, identity ambiguity, preservation/validation, cursor ordering, cancellation, commit sequencing, redacted output and source XML privacy rules. CI runs the actual JUnit suite, Android lint/build and APK signature/checksum validation. This does not substitute for Room migration/rollback tests, real Xiaomi account requests, actual scale hardware or Android/OEM backup behavior.

There is no new Room schema or authenticated HTTP transport. Persistent subject binding, canonical observations, session storage, normal challenge handling, live sync UI and Health Connect write-back remain next work. CN/global describes the request region, not verified compatibility with every regional scale. S400 Pro is still unverified.

The existing publicly known signing key is TEST-ONLY and cannot authenticate the publisher against another holder of that key. Do not use it as the trusted channel for routine real Xiaomi credentials. A private signing/migration strategy needs an explicit owner decision before enabling that path.
