# Fitness Hub 0.3.4 — Xiaomi transport and session prerequisites

Pre-alpha test build. Same app ID/test signing key; database schema remains 6.

## Added

- Three-step xiaomiio authentication component, with explicit CAPTCHA/additional-verification detection and no stored password/passToken.
- Scope-bound read-only scale requests, nonce/signature/encryption compatibility and strict HTTPS endpoint policy.
- Bounded asynchronous HTTPS adapter with cancellation and static error codes.
- AndroidKeyStore/AES-GCM session file outside Room and backups; expiry, corruption and logout handling.
- Coordinator connecting authenticated page reads to existing transactional Room import.
- Synthetic protocol, transport, session, cancellation and native Room integration tests.

## Not yet enabled on the phone

The test APK does NOT expose an operational Xiaomi login screen. Production assembly remains blocked until the owner-approved private signing policy is implemented. The components are tested using synthetic responses; no real Xiaomi account, S400 Pro hardware or Redmi Keystore has been validated.

CAPTCHA/2FA completion, onboarding/profile selection, periodic Xiaomi sync, canonical UI integration and Health Connect write-back remain unfinished. No new server, paid service, root requirement or external bridge was introduced.

## Data safety

Do not uninstall a build containing valuable data. Backup v2 limitations remain: database tables only, same schema, conservative merge, no credentials/preferences/media. A session logout must not delete health records. See docs/connectors/xiaomi-auth.md and docs/PROGRESS.md for scope and verification.
